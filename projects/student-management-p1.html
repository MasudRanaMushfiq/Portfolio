Student Management P1

A student management system with authentication via Laravel Breeze, role-based access control, and full student CRUD with an admin dashboard.

Problem

Educational institutions needed a streamlined system to manage student records, user roles, and administrative tasks. Manual processes were error-prone and time-consuming.

Solution

Developed a full-stack student management system with Laravel Breeze authentication, role-based access control (admin/teacher/student), and complete CRUD operations for student records.

Key Features

  • Laravel Breeze authentication scaffold
  • Role-based access control (Admin, Teacher, Student)
  • Full student CRUD with validation
  • Admin dashboard with statistics
  • Responsive Tailwind CSS interface

Challenges & Engineering Deep Dive

Role-Based Access Control with Spatie Permission

The system serves three distinct user roles — Admin, Department, and Exam — each with different permissions. Admin can manage everything; Department can manage student records and admit students; Exam handles marks, results, and academic data. Implementing this cleanly without hard-coding role checks throughout the codebase was a design challenge.


How I solved it: Used Spatie Laravel Permission to define roles and permissions via database seeders, then created custom middleware aliases (role:admin, role:department, role:exam) registered in bootstrap/app.php. Each route group in web.php applies the appropriate middleware. The @can Blade directive conditionally renders UI elements per role, while the sidebar menu adapts based on the authenticated user's role using the @role directive.

Modular Architecture with nwidart/laravel-modules

As the project grew, placing all controllers, models, and views inside the default Laravel app/ directory became unmanageable. Student-specific logic was mixed with general auth and dashboard code, creating coupling that made future refactoring risky.


How I solved it: Adopted the nwidart/laravel-modules package to organize the codebase into isolated modules. The Modules/Student directory contains its own Controllers, Models, Routes, Views, and database migrations — fully self-contained. Laravel auto-discovers modules via the module Providers namespace, and the artisan module:make command scaffolds new ones. This separation means the Student module could be extracted into a Composer package later with minimal effort.

Audit Logging for Data Integrity

Educational institutions need a tamper-proof record of who changed what and when. Without an audit trail, a student record could be deleted or modified with no accountability — a serious issue for compliance and trust.


How I solved it: Created an AuditLog model that captures the authenticated user ID, the affected model type and ID, the action performed (created/updated/deleted), and a JSON diff of old vs. new values. A custom Auditable trait on the Student model hooks into Eloquent events via booted() — automatically logging every create, update, and delete. The Admin dashboard displays these logs in a searchable, paginated table with color-coded action badges.

PDF Export of Student Records

Administrators needed to generate downloadable PDFs of student records for offline filing, printing, and official documentation. Generating these from Blade templates with proper formatting, margins, and pagination required a specialized tool.


How I solved it: Integrated barryvdh/laravel-dompdf — a DOMPDF wrapper — to render Blade templates into PDFs. Created a dedicated student.pdf.blade.php view with print-friendly styling, and a downloadPdf() controller method that returns PDF::loadView(...)->download(). The Export button in the student list is role-gated so only Admin and Department users see it.

Multi-Portal Dashboard Architecture

Each role (Admin, Department, Exam) sees a different dashboard with different metrics, navigation, and actions. Cramming all three into a single dashboard view would create messy conditional logic and hurt maintainability.


How I solved it: Created three separate dashboard controllers — AdminController, DepartmentController, and ExamController — each within the appropriate module. Each controller queries only the data relevant to its role. The layout file uses Bootstrap's sidebar navigation that conditionally highlights menu items based on the user's role. Route groups are prefixed and middleware-gated so users can only access their own portal.

REST API Versioning with Sanctum Auth

The system exposes a /api/v1/students endpoint for mobile or third-party integration. Designing the API with proper versioning, authentication, error responses, and rate limiting required careful planning to avoid breaking changes later.


How I solved it: Placed all API routes under routes/api.php with the /api/v1/students prefix. Used Laravel Sanctum for token-based authentication — users generate tokens via the dashboard and pass them as Bearer tokens. Responses use Laravel's Resource classes for consistent JSON structures, and validation errors return a standardized 422 with field-level messages. The ensureFrontendRequestsAreStateful middleware allows SPA authentication to co-exist with API token auth.
